1. Add a mouse adapter to the same intent-to-motor path used by keyboard controls. Relative horizontal motion steers yaw; relative vertical motion pitches the nose. Holding the primary mouse button supplies propulsion; releasing it invokes P6's passive slowdown. A secondary-button press opens pause/options. These are provisional bindings for P10, not new owner-selected button assignments. Add no mouse brake, reverse swimming or free-look mode.
2. Accumulate relative movement safely and consume it exactly once. Avoid multiplying integrated pixel displacement by frame time again, applying events in both input and physics callbacks, or retaining a large steering backlog. Motor integration remains physics-delta-based. Clear pending motion at capture, focus, pause and mode boundaries; guard against synthetic recenter/warp deltas. Expose sensitivity and inversion through the existing compact options flow as documented tuning defaults.
3. Keep mode selection explicit. Only the selected adapter generates swimming intent; incidental motion cannot switch modes. Switching neutralizes both adapters and requires fresh propulsion input. Reuse the menu/focus system: mouse-only users can select a mode, pause, resume and operate relevant options without keys; keyboard users can do the same through focus navigation and activation.
4. Implement consistent input ownership across gameplay and menus. Consume the action that opens/resumes a menu so it cannot become propulsion or steering. Suppress menu-owned input until released before rearming gameplay. Focus loss pauses the local test simulation and clears held/queued input; returning focus leaves an explicit resume step. Release mouse capture for menus and restore it deliberately. Preserve both display choices, the fresh-profile Fullscreen default, saved-choice/temporary-override behavior and supported transitions.
