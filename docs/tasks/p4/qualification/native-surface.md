## Scoped repair and verification

The first Pond→Ocean→Pond run visibly loaded both worlds but printed `System.InvalidOperationException: Handle is not initialized` from `Godot.Bridge.ScriptManagerBridge` during `CharacterSelect.EnterWorld()` / `SceneTree.ChangeSceneToFile()`. A fresh paced switch did not reproduce it. Rapid repeated activation before the previous scene was removed was a plausible trigger, so `CharacterSelect` now guards Enter and Back transitions and reports a failed scene change to the page. A focused route check emits Enter twice before `SceneChanged`; `tools/dev build` and `tools/dev inspect-character-select` passed. A fresh native rapid-click Pond→Ocean→Pond retest loaded `FAF-FISH-006`, `FAF-FISH-001`, `FAF-FISH-006` once each with no `ERROR:` or `SCRIPT ERROR:` in the [retained log](native-surface-evidence/native-retest.log). This verifies the observed rapid-click route, not every scene transition or engine condition.

Two temporary water-surface alpha reductions were compared in the same native seed and did not make the submerged body readable from above. The original shader was restored; no unreviewed water-look change remains. The code repair does not cure the V32 visual failure. No self-commit or push was made.
