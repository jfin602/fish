GOAL
Provide a usable in-game pause/options Control Presets editor with rebinding, custom profiles and safe apply/revert, without bloating the test-session shell or losing keyboard-only/mouse-only menu access.

PREREQUISITES AND NARROW READING
Read AGENTS.md, BOOT.md, c1-bindings README.md and implementation-plan.md P3, P1/P2 code/evidence, docs/ux-and-presentation.md focus/display sections, and actual PlayShell.cs, DisplayPreferences.cs, new preset model/store/resolver, runtime scene and relevant focus tests. Confirm root 0.1.9, expected correction P1–P2 completion, Fish repo identity and unrelated changes before editing.

IMPLEMENT
1. Extend the existing pause/options surface with a distinct Control Presets panel reachable by button and keyboard focus. Show built-in and custom named profiles and active/edited distinction; built-ins cannot be overwritten, but can be duplicated. Support Create/Save As, Duplicate, Rename, Delete, Reset, Save/Apply and Revert (with confirmation for destructive operations). Keep a recoverable prior selected profile if an edit or apply is cancelled.
2. Display semantic actions with their current key/button bindings, support multiple bindings per action and remove/replace. Clicking a rebinding row begins a clear modal capture state and captures only a new physical keyboard key or mouse button. Use a separate explicit editor for mouse X/Y steering direction and sensitivity/inversion; do not capture incidental pointer movement as a key/button. Detect and explain conflicting assignments; disallow ambiguous competing actions or require explicit conflict resolution. Preserve unbindable reliable Pause/Escape/menu recovery.
3. Consume captured or UI-activation events so they cannot simultaneously trigger movement or dismiss the menu; handle Escape as cancel during capture, not as a destructive rebind. Manage pointer release/recapture and focus correctly when entering, exiting, applying, pausing or losing window focus. Both mouse-only and keyboard-only players must be able to open, edit or exit settings. Keep show-controls help derived from current active bindings.
4. Keep layouts usable in fullscreen and windowed fullscreen, including smaller windows. Reuse Godot Controls and minimal C# view/state components; avoid new art/dependencies and a general settings editor. Preserve the existing display controls, menu buttons and project renderer.
5. Add focused UI tests for profile creation/duplicate/rename/delete/save/reload, binding a new key/mouse button, conflicts, safe cancel/reset, apply/revert, tab/keyboard focus, pointer selection and no input leak through Resume.

SCOPE / DEFERRALS
