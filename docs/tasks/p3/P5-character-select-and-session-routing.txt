IMPLEMENT
1. Add a dedicated Character Select scene/page that becomes the normal P3 session entry before gameplay.
2. Show the selected fish as a real animated 3D preview using its tracked FAF model/rig. Prefer a calm Glide/Swim loop; preview animation must not translate the model through the scene. Display the fish's readable name and selection state.
3. Provide clear mouse + keyboard browsing/selection and a Start/Play action. All five choices must be reachable; focus/hover/selected state must not rely on color alone. Keep layout readable at the current fullscreen/windowed-fullscreen targets.
4. Add one small **session-local character selection owner** (or equivalent existing app/session boundary) storing only the selected FAF fish ID while the app is running. Do not write it to disk or call future run-save code.
5. Refactor the player visual attachment only as needed so normal play instantiates the selected FAF model under the existing authoritative FishController. Preserve the one CharacterBody3D, collider, SwimMotor, swim tuning, controls, FollowCamera and WaterReaction.
6. Give each selectable fish an explicit presentation normalization transform (scale/orientation/visual offset as needed) so Yellow Tang, Clownfish, Chromis, Butterflyfish and Blacktip Shark fit the existing shared player presentation envelope. Do **not** resize the authoritative collider or retune movement/camera per species in P3.
7. Map each selected rig to its existing Glide/Swim/SwimFast clips through one player-visual/animation boundary. Preserve animation-only root behavior; the rig cannot move the gameplay root.
8. Add **Return to Character Select** to the in-game Pause/Game Menu. When activated:
   - clear/disarm held/queued gameplay input;
   - release mouse capture/show pointer;
   - unload/reset the current ephemeral gameplay scene/session;
   - return to Character Select;
   - optionally keep the last selected fish highlighted in memory.
   It must **not** mark death, write a life-history entry, save/resume a run, invoke New Life/abandon-life semantics, or advance gameplay time while on the selection page.
9. Starting again after return creates a fresh P3 tech-demo play scene with the newly selected visual. This is session routing only; later persistence will define real living-life replacement rules.
10. Add focused checks for:
   - stable catalog of five selectable IDs/names;
   - all five preview scenes/animations load;
   - each selection starts play with the corresponding player visual;
   - FishController/collision/tuning/control/camera identities remain identical across all five choices;
   - shark visual normalization cannot change collision or speed;
   - Return to Character Select clears input/capture and removes gameplay-session nodes;
   - no death/save/history path fires;
   - selection page can start a second different fish after return.
11. Record implementation/check results in `docs/tasks/p3/qualification/implementation.md` and create/update `qualification/character-select.md` only for evidence actually observed.
