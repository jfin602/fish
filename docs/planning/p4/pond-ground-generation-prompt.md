# Pond FAF ground-dressing generation prompt

**Use:** Standalone implementation prompt for the Pond's first ground-dressing pack. It creates reusable materials, small assets and an isolated placement proof, not the primary Pond terrain or a P4 Gate result. Work in a separate checkout if other Pond packs are running concurrently; coordinate shared FAF IDs and helper files before merging.

## Prompt

Create an original **Pond Fish Asset Factory ground-dressing pack** for Fish using `/home/jfin/best-pond-faf.png` as the visual reference. Build a shared, low-poly-compatible **silt/mud/wet-bank/algae palette** and a small reusable detail family: **two eroded-bank edge pieces, two algae-coated stones, two pebble clusters and two leaf-litter clusters**. These eight geometry variants are a bounded starting kit; the silt/mud surface treatment should primarily live on the generated pond terrain, not in a carpet of overlapping floor tiles. Deliver editable Blender sources, individual clean GLBs for the geometry, reusable Godot materials, a manifest, focused checks and an isolated Forward+ density/ground-contact proof.

### Materials and eight geometry variants

- **Shared terrain palette/materials:** Define coherent silt, soft mud, wet bank and algae-coated stone color/roughness regions. Use broad, low-frequency transitions and restrained face/vertex variation that survives underwater Forward+ lighting. The generated pond basin remains the primary playable floor; these materials and small accents should dress it rather than cover it with duplicate geometry. Document how shallow, middle and deep lighting changes their appearance without silently retuning Ocean materials.
- **Eroded bank — two pieces:** Make different irregular low-poly edge/shoulder shapes, one gentle undercut and one root/stone-scarred slope. They must embed into a sloped shoreline with a clear contact/skirt strategy, no flat plate hovering over the bank, and no hard repeated rectangular edge. Keep any meaningful solid bank extension aligned with simple collision; do not create a visual ledge the player can pass through.
- **Algae-coated stones — two pieces:** Make two distinct asymmetrical faceted stones with algae limited to sheltered/upper regions, rather than recoloring an entire reef rock green. Ground-contact pivots and support footprints must be clear. Use simple collision only if a stone is large enough to affect fish movement.
- **Pebbles — two clusters:** Make inexpensive irregular groups with different count, footprint, size mix and color. Keep them low and readable in close shallows; they should not turn into miniature boulders or vanish due to ground clipping.
- **Leaf litter — two clusters:** Make low-cost scattered leaf shapes with different orientation, overlap and decay color. Use a few broad faceted leaves rather than many alpha cards; keep them near the ground and out of the main swim lane. Do not animate every leaf or add expensive collision.

Use metres, useful ground-contact pivots, identity export transforms, named shared materials and measured triangle/material counts. Variants must differ in form, not only tint. Keep close-up details quiet enough that fish, log openings and routes remain readable. Do not add food pickups, particle effects, decomposition simulation, collision to tiny debris or gameplay interaction in this asset task.

### Placement, export and proof

1. Save editable first-party `.blend` masters and reproducible generator/recipe code where used. Export one GLB per geometry variant with only intended meshes/materials. Add Pond material resources or a documented material palette that can be applied to the future generated basin without replacing the Ocean palette. Record FAF ID, role, source/export path, dimensions, measured triangles/materials, palette, pivot, support footprint, placement zone, collision rule, generator/seed and technical/style state in a manifest.
2. Define a deterministic **placement contract** for later Pond integration: sample the finished terrain height and normal; orient and partially embed each detail according to its support footprint; favor shallow banks, wood/stone contacts and sheltered pockets; avoid steep unsupported spans, protected routes, hollow-log entrances and uniform grids. This task may prove the rules in an isolated fixture but must not change the shared world compiler or normal play.
3. Build an isolated Godot Forward+ proof with a sloped muddy bank, waterline, shallow/middle/deep light samples and a representative fish-camera view. Show every variant alone, then a sparse and a denser mixed patch beside a log or stone. Inspect from above and underwater for hovering, z-fighting, buried pebbles, leaf clipping, visible bank-piece seams, repetitive color bands and blocked routes. Measure representative draw/triangle cost; use instance reuse and no small-detail collision by default.
4. Add focused checks for exact eight-variant inventory, unique Pond IDs, GLB import, dimensions/transforms, named materials, ground-contact pivots, support bounds and deterministic fixed-seed output where generated. A headless check cannot prove no floating pieces in an actual sloped scene, so record native visual observations separately. Capture family overviews and gameplay-distance density images with source revision, Blender/Godot versions and actual checks/results.

### Done condition

The pack is technically complete when the shared silt/mud/wet-bank/algae palette and all **eight** bank/stone/pebble/leaf variants have editable sources, correct runtime resources, manifest identities and focused import checks. Native proof must show grounded placement on varied slopes, broad natural color variation, no floating or deeply buried details, no artificial tile grid and inexpensive repeated scattering that leaves routes clear. Report passed, failed and unobserved criteria honestly; isolated dressing does not complete a P4 world Gate.
