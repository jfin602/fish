# Reusable generators

Do not create each successful asset as an unrelated one-off. When a form works, extract repeatable construction logic into its family generator and keep the source in [FAF tooling](../../tools/asset-factory/README.md). Parameterize the meaningful choices: fish body families, fins, fish rigging/weights, branching and plate coral, boulders/arches, kelp/grass and terrain chunks. Keep shared naming, palette, validation and export rules central.

The first reusable rock generator is [FAF-ROCK-001](rock-001/README.md), with deterministic broad-mass and planar-cut construction in [`rocks.boulder`](../../tools/asset-factory/blender/rocks/boulder.py). Its A/B/C/D recipe remains separately recorded. Future generators need a clear input contract, deterministic seed where variation is random, stable ID handling, meaningful parameters and a visual review loop. Generated `.blend`/`.glb` outputs are inspectable artifacts; a transient Blender MCP Python command alone is not a reusable generator. Add family logic only while building an actual reviewed asset, and preserve source/version in its [candidate record](blender-godot-contract.md#candidate-record).

The first reusable coral generators are [FAF-CORAL-001–004](coral-pack-001/README.md), with branching, rounded, tube and fan geometry APIs in [`coral.families`](../../tools/asset-factory/blender/coral/families.py), a fixed twelve-variant [recipe](../../tools/asset-factory/blender/coral/build_pack_001.py), and a [per-asset manifest](../../assets/faf/coral/coral_001_to_004_manifest.json). Each family has meaningful form parameters and a seed; future candidates require visual and native review rather than direct production placement.
