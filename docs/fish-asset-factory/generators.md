# Reusable generators

Do not create each successful asset as an unrelated one-off. When a form works, extract repeatable construction logic into its family generator and keep the source in [FAF tooling](../../tools/asset-factory/README.md). Parameterize the meaningful choices: fish body families, fins, fish rigging/weights, branching and plate coral, boulders/arches, kelp/grass and terrain chunks. Keep shared naming, palette, validation and export rules central.

The first reusable rock generator is [FAF-ROCK-001](rock-001/README.md), with deterministic broad-mass and planar-cut construction in [`rocks.boulder`](../../tools/asset-factory/blender/rocks/boulder.py). Its A/B/C/D recipe remains separately recorded. Future generators need a clear input contract, deterministic seed where variation is random, stable ID handling, meaningful parameters and a visual review loop. Generated `.blend`/`.glb` outputs are inspectable artifacts; a transient Blender MCP Python command alone is not a reusable generator. Add family logic only while building an actual reviewed asset, and preserve source/version in its [candidate record](blender-godot-contract.md#candidate-record).

The first reusable coral generators are [FAF-CORAL-001–004](coral-pack-001/README.md), with branching, rounded, tube and fan geometry APIs in [`coral.families`](../../tools/asset-factory/blender/coral/families.py), a fixed twelve-variant [recipe](../../tools/asset-factory/blender/coral/build_pack_001.py), and a [per-asset manifest](../../assets/faf/coral/coral_001_to_004_manifest.json). Each family has meaningful form parameters and a seed; future candidates require visual and native review rather than direct production placement.

The first reusable vegetation generators are [FAF-PLANT-001–003](plant-pack-001/README.md), with three form-specific APIs in [`plants.families`](../../tools/asset-factory/blender/plants/families.py), an eight-variant [recipe](../../tools/asset-factory/blender/plants/build_pack_001.py), and a [per-asset manifest](../../assets/faf/plants/plant_001_to_003_manifest.json). The geometry reserves UV.y as a base-to-tip mask for later presentation-only sway; the generators do not author motion or placement.

The first reusable terrain builder is [FAF-TERRAIN-001](terrain-001/README.md), with `terrain_geometry(TerrainSpec)` / `create_terrain(...)` in [`terrain.patch`](../../tools/asset-factory/blender/terrain/patch.py), six fixed macro-profile [recipes](../../tools/asset-factory/blender/terrain/build_001.py), and a [per-chunk manifest](../../assets/faf/terrain/terrain_001_manifest.json). Its common zero-height irregular apron supports authored overlap. It creates broad visual surfaces only; collision and seam dressing belong to scene composition.

The first varied fish library is [FAF-FISH-001–005](reef-fish-pack-001/README.md). New [species blueprints](../../tools/asset-factory/blender/fish/reef_families.py) for FAF-FISH-002–005 supply distinct loft stations, fin recipes, bone chains, materials, and motion profiles while reusing FAF station weights and Action generation. The [pack builder](../../tools/asset-factory/blender/fish/build_reef_pack_001.py) writes an editable four-scene Blender source, separate GLBs, and a [configuration manifest](../../assets/faf/fish/reef_fish_002_to_005_manifest.json). There is no universal fish silhouette; the shark has its own fin recipe and wave profile. For multi-scene files, export species-owned NLA tracks so unrelated Actions cannot leak into a GLB.

Every future fish generator follows: geometry → explicit breathing anatomy classification → base body rig → anatomy-specific breathing rig → body weights → localized breathing weights → swimming Actions → source and breathing validation → selected GLB export → exported-skeleton validation. `fish.breathing` owns the reusable `OperculumSpec`, `add_operculum_rig`, `weight_operculum_region`, `validate_breathing_rig`, and `validate_exported_breathing` checks. The blueprint must state `operculate_bony` or an explicit species-appropriate type; no default of “none” is permitted. Ordinary bony fish gain paired gill bones automatically in `create_fish`, with species/head dimensions derived from their loft and eye placement. The Yellow Tang's original sculpt uses its own anatomical coordinates through the same helpers. New breathing types need their own implemented deformation and strict validator before final technical acceptance. A pending type can be recorded as a candidate but fails strict completion.

The first small-detail pack is [FAF-DETAIL-001–004](detail-pack-001/README.md). Four narrow geometry APIs in [`details.families`](../../tools/asset-factory/blender/details/families.py) build shells, fracture rubble, pebbles and sponge cups from meaningful metre-scale proportions, counts and local seeds. The [eight-variant recipe](../../tools/asset-factory/blender/details/build_pack_001.py) writes a [candidate manifest](../../assets/faf/details/detail_001_to_004_manifest.json), one editable master and separate GLBs. Keep these supporting forms sparse; do not expand them into a universal debris generator without an actual new asset need.

The [FAF-FISH-001–005 developmental family](life-stages-001/README.md) uses [`fish.life_stages`](../../tools/asset-factory/blender/fish/life_stages.py) to specify per-species stage size, body/head/fin proportions, palette, markings and wave behavior. The [builder](../../tools/asset-factory/blender/fish/build_life_stages.py) emits 20 additional assets and a [manifest](../../assets/faf/fish/life_stages_001_to_005_manifest.json); five canonical adult assets remain separate. Shared loft, rig, weights, Actions and export apply where anatomically appropriate. Stage color is explicit rather than inherited unchanged from the adult; early camouflage can give way to more visible adult markings. This is visual asset data, not gameplay growth logic.
